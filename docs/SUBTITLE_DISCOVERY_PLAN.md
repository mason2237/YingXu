# 可选字幕库接入计划

更新：2026-10-24。以现有离线工作台和文件整理核心为基础增量开发，不重做前八阶段。

## 最新增量（阶段十）

用户要求解决打开闪烁、搜索引导不足、完整文件名搜不到、下载自动解压、缓存入口和字体问题。已按“确认片名 → 选择并下载 → 核对匹配”补齐：自动生成的搜索词只保留片名；原名仍用于匹配评分；下载后默认自动解压并登记，保留手动导入开关及原确认流程。新增 ZIP 之外的系统 tar 有界 RAR/7z 读取，失败保留原包并展示原因；缓存入口在右上角，避免自动删除正在审阅的字幕。工作台首帧等待主题/字体/绘制就绪，中文离线使用 Noto Sans SC。版本 `0.9.0-rc.3`，验收和续接见 [STAGE10_UX_FIXES.md](STAGE10_UX_FIXES.md)。历史阶段的格式/导入限制是当时的结论，以本段和当前 README 为准。

## 最新实站结果（9e）

真实 SubHD 查询已取得 ASS 并导入到当前审阅为“需确认”；修复了其同源 blob 文件被旧接收器误拒绝的问题，发布候选升为 0.9.0-rc.2。实测 1 份、251,040 字节；字幕库主站仍显示验证码。网站下载按钮本轮由测试点击，程序尚未自动触发，不是无人值守批量下载。网页片源和本地视频版本仍须核对。见 [STAGE9E_LIVE_DOWNLOAD.md](STAGE9E_LIVE_DOWNLOAD.md)。

## 已确认的决定

- **zimuku.org 优先，尽量减少手动操作**；不要求配置 API Token。
- 批量选择视频，最终接入主工作台时默认选中未匹配字幕的视频。
- 中英双语优先，语言优先级可设置并保存。
- 集中展示推荐；允许更换和跳过，低可信结果需人工确认。
- 用户已确认使用独立内置网站窗口：自动准备搜索词，尽可能自动接收下载、导入及匹配。网站必要的验证码或登录由用户完成。
- 下载不代表匹配成功；最终文件放置仍须预览、明确确认、不覆盖。
- 不上传视频，不增加自动时间轴同步。系统浏览器作为兼容回退，其下载接收需单独设计。

9d 补测：用户要求再次测试后，原生目录选择、EXE 扫描/确认/实际整理/结果记录与在线入口通过，本机核心验收已完成。在线网站真实下载认证仍未完整验收；本轮没有对外上传。

- `run_subtitle_browser.py`：显式开发入口；默认 `run_web.py` 和现有发布包保持原入口。
- `yingxu/web_ui/subtitle_browser.py`：独立原生窗口和 QWebEngineView，搜索队列、网站导航、下载接收。
- `yingxu/subtitle_sources/zimuku.py`：站点地址策略、视频搜索词、基于当前实际 DOM 的搜索表单填写脚本。
- `yingxu/subtitle_sources/downloads.py`：受控暂存路径、文件名净化、初步格式识别、独占创建收据。
- `yingxu/subtitle_sources/websites.py`：站方公开的域名清单；`subhd.py` 适配已实际观察的搜索控件。
- `candidates.py`：有界 DOM 读取、详情地址校验和可解释排序；`subtitle_recommendations.py`：原生候选面板。
- `imports.py`：安全准备直接字幕/ZIP 副本。`review.py` 增量登记导入元数据，导入副本最终目标为视频目录；原本地字幕规则保留，`core.py`、`operations.py` 未改。
- 生产 QWebChannel 仍只增加 `subtitle.open(scanId, revision, rowId?)`；导入使用原生信号和已登记下载 ID，不接收网页路径或 URL。后台任务发布新版审阅，原预览/确认凭证失效。

远程页面不注册 QWebChannel、不安装本地资源处理器。独立 off-the-record profile 的 Cookie 在窗口内有效，不继承系统浏览器登录、不持久化登录。网络页面不能弹出文件选择器上传视频，权限请求被拒绝；证书错误不忽略。

## 必须保留的限制

- Qt 实测确认字幕库及 srtku.com 返回的是访问验证码页（HTTP 404）；SubHD 两条线路实际搜索成功。保留真实页面适配，不假设未验证路由。
- 当前表单适配只在字幕库域名、可见且唯一的明确搜索框、同站 HTTPS 提交目标下运行；未识别时保留网页操作、再次填入、复制搜索词和浏览器回退。
- 站外主页面跳转被拦截，可能影响下载外链/验证流程；在实际兼容性证据出现后再定向调整，不泛化授权其他站点。
- HTTPS/地址筛选是 URL 策略，不是 DNS 防火墙；保留 Chromium 原有的隔离与权限机制。
- 原型每份下载上限 64 MiB、每窗口累计 256 MiB、20 份文件、同时最多两份；未知大小在进度中检查。暂存文件不自动打开或执行。
- 下载事件可能由网页自动触发，不作为用户明确点击或已匹配的证明；收据记录搜索任务线索，并固定 `matchConfirmed=false`。
- 格式头仅用于下载初检；9c 对 ZIP 另做路径/条目/大小/压缩比/内容边界检查，只准备到暂存目录。RAR/7z、加密/分卷/ZIP64、嵌套压缩及 IDX/SUB 配对不导入。最终匹配须核对实际文件，不从网页推荐推定正确。
- 暂存包含候选、被拒绝和未完成的文件；本阶段不自动清理，用户可通过“打开暂存目录”自行处理。会话限额不代表跨窗口磁盘配额。

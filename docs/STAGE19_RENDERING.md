# 阶段十九：代码与渲染优化

2026-10-25，版本 0.9.0-rc.12。本轮按用户要求优化现有架构，保留 Python 核心、网页交互、上游玻璃和果冻效果、可选原生 HDR，不迁移框架。

## 修改

- 修复按钮样式观察器的自触发循环：对已没有玻璃类的结构按钮反复调用 `classList.remove`，仍会产生属性变更，导致每帧重新遍历按钮。现在只在属性确实改变时写入。
- 液态按钮的裁剪路径按值更新，避免渲染器自身的样式写入不断延长绘制周期。玻璃启停和任务忙碌状态同步保持幂等，并保留 GPU 丢失后的恢复入口。19 个原始 Lens 文件未修改。
- 虚拟列表最多缓存 60 条；选中项变化复用可见节点和数据，相邻滚动复用缓冲。同一页请求合并，扫描 ID、数据版本和筛选条件共同隔离缓存；旧请求不得覆盖新视图。可见行只增加、删除或替换实际变化部分，文件名仍通过纯文本展示。
- SDR 主窗口直接显示 WebEngine，不创建整页 HDR 纹理及着色器。实际 scRGB 交换链才加载 HDR 层；保留纸白校正和高光效果。
- HDR 弹窗不再在整个打开期间每 16ms 强制复制纹理；正常画面随 WebEngine 更新，打开/关闭仅补 8 帧。最小化时停止纹理实时更新和补帧，不销毁图形资源。
- 页面重载/渲染终止时清理旧回调、就绪探针和弹窗状态；就绪查询最多一个在途，旧页面返回值不能揭开新页面的启动遮罩。不可见窗口跳过系统显示状态轮询。

无新依赖、持久化格式或文件操作接口；`--widgets` 兼容入口保持。用户视频、下载缓存和设置不作迁移。

## 验证

- 同一机器、相同暗色/HDR 空闲窗口，1 秒观察期间的 class 变更由 244 次降为 0。两版采样时原生呈现均为 0 帧，说明此指标证明的是消除无效 DOM/脚本工作，不应宣称 GPU 帧数或整机性能提升倍数。
- HDR/SDR 的 600ms rAF 采样均正常推进，最大间隔约 16.8ms。这是本机短采样，不是复杂场景持续帧率保证。
- 5000 条结构化数据：节点和请求缓存复用、筛选与扫描 ID 失效、乱序响应、在途请求合并、空列表恢复和文件名纯文本通过。
- 真实 Qt 窗口：两种输出下各 4 次设置关闭，包含滚轮、淡出中间帧、焦点返回；弹窗静止时补帧停止。退出中重开、减少动态、明暗切换、940/1280 宽度、最小化恢复和重载通过。
- HDR/SDR 均实际扫描 120 个临时视频，经 PageDown 和 8 个实际送达网页的 Qt 滚轮事件后滚动至 495px，5 行处于可见区域、17 个行节点；文件内容及数量保持，未执行整理。检查器使用 QTest 输入接口并核对事件数量，避免把没有送达的手工事件当作通过。
- 57 个不同的外观、渲染参数、受限通信、上游来源及核心/审阅/操作回归用例通过。沙箱下 QSettings 保存导致外观组 5 项失败；仅该组 11 项在正常 Windows 权限下重验通过，未放宽产品保存检查。
- 初始测试模块相对地址无法从原生注入脚本解析，改为由当前页面生成绝对地址。Qt 的 `QQuickWindow.grabWindow()` 在本机 HDR 交换链返回错误像素解释，改用系统合成后的单张窗口截图；截图只能检查布局与可见内容，不作为 HDR 物理亮度证据。检查器失败记录保留。

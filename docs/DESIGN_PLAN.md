## 界面方向

中性灰白、深灰正文、少量品牌蓝。既有 Qt 基线为中文正文 11pt、辅助文字 10pt 起；Web 版正文约 15–16 CSS px、辅助 13–14px，实际 Windows 窗口中验收。
统一 4/8/12/16/24 间距、Web 版 6–10 圆角及约 36–40 逻辑像素控件高度；不直接混用 CSS px 与 Qt pt。
保留系统标题栏，统一悬停、按下、禁用、焦点等状态。
第六阶段加入局部液态玻璃（顶部工具栏、浮层、选中控件的轻折射/高光/按压反馈），文件列表保持清晰稳定。
粒子仅用于空状态或整理完成时的短暂反馈，低密度、可关闭；减少动画时自动简化，低性能设备可降级为普通材质。实际窗口验收后决定保留程度，第八阶段统一细修。

布局：紧凑品牌/目录/扫描工具栏 → 搜索与带数量的筛选 → 主列表和可伸缩详情 → 状态反馈。
取消大侧栏、装饰插画及大数字卡片；列表是主体。
列表每行分层展示视频与字幕，右侧显示状态及匹配依据；支持搜索、排序、键盘选择。
长名称保留有用的集数、语言、扩展名，详情可完整查看、复制。
详情支持人工换字幕、确认匹配、跳过与恢复；人工指定不显示为自动匹配 100%。
变更预览独立呈现源名称、最终名称、目录变化、冲突编号，确认后才执行。
预览后文件状态变化必须报告并要求重新检查，不悄悄生成不同目标。

| 优先新增 2 | 候选字幕对比 | 阶段 3，提升异常处理效率，展示评分依据并支持人工选择 |
| 优先新增 3 | 多语言字幕匹配 | 阶段 3，独立处理一对多关系与命名冲突；逐份预览 |
| 整理闭环 | 本地操作记录 | 阶段 4，与真实执行结果一同写入 |
| 可选增强 | 安全撤销 | 阶段 4，在记录与身份检查可靠后实现，单独验收 |

以上是实现先后顺序；可选增强不应延迟主流程交付。扩大范围前在阶段汇报中说明工作量及影响。

## 验证要求

功能：普通/无视频/无字幕、中文长文件名、集数冲突、低可信匹配、人工重复分配、命名冲突、源消失、路径权限异常、中止与重复操作。
安全用临时样本验证：确认前零媒体文件改动、已存在目标不覆盖、文件内容保留、统计准确。
视觉：实际启动后检查字号/对齐/留白/滚动/焦点/缩放；100/125/150/200% 检查，真实系统与模拟检查分别记录。
构建：每阶段至少验证源码运行；框架迁移阶段提前试打包，最终 EXE 实际启动。不得将当前机器启动等同于干净系统认证。

## 维护边界

业务核心保持纯 Python；旧 Qt UI 保留，新版由本地 Web 展示、受限 QWebChannel 传 DTO、Python 服务管理计划/任务，后台事件异步更新。
不为了视觉更换匹配算法；必要的行为修正单独记录并补充针对性验证。
固定依赖版本，构建路径相对项目解析；后续模型先读 PROGRESS 和相关模块，避免重复全量探索。

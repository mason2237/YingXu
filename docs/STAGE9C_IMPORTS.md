# 9c：下载字幕导入与确认整理

日期：2026-10-24。用户在 9b 完成汇报后确认“继续”，本阶段完成后暂停，等待 9d 确认。

## 用户流程

1. 从工作台打开“在线字幕”，在网站下载字幕。
2. 已登记下载默认勾选；可取消不需要的项目，点击“导入并返回审阅”。
3. Python 后台检查实际文件，只把副本准备到私有缓存。多版本字幕登记为候选；只有单份且原视频未匹配、未跳过时自动关联为“需确认”，已有匹配保持。
4. 在工作台核对实际字幕名称、语言、集数和片源；必要时选择、更换、添加语言或跳过。候选排序不依赖随机缓存目录名，完整缓存路径可展开。
5. 确认匹配后打开最终预览，看到缓存源文件和视频目录目标。勾选“已核对”再整理，沿用原不覆盖执行器和本地记录。

下载推荐只是线索；软件不判断字幕时间轴或不同剪辑版本是否完全一致。文件名相似度明确标为非概率。

## 实现与边界

| 位置 | 变化 |
| --- | --- |
| `yingxu/subtitle_sources/imports.py` | 有界 ZIP/直接字幕读取，缓存独占副本，内容初检、路径和身份校验 |
| `yingxu/review.py` | 导入元数据、候选库存、单份待确认关联；只对导入文件设置视频目录目标 |
| `yingxu/web_ui/workspace_service.py` | 原生登记 ID、后台导入、版本更新、重复阻止、旧预览撤销、导入副本变更复查 |
| `yingxu/web_ui/workspace_data.py` | 在线来源提示、候选优先级、实际名称/路径 DTO |
| `yingxu/web_ui/subtitle_browser.py`、`window.py` | 下载勾选、导入/返回审阅、逐项失败信息、后台完成和关闭处理 |
| `frontend/js/components/` 与 `workspace.js` | 原生导入任务完成后刷新、陈旧预览禁用、实际候选入口、缓存路径折叠、扫描/导入提示 |

- `core.py`、`operations.py` 不改。历史 Qt/离线流程保留；本地字幕 `move=False` 仍在原字幕目录命名，导入副本最终放到视频目录。
- 无新增依赖；使用 Python 标准库 `zipfile`。不安装或调用解压程序，不执行包内脚本或递归处理嵌套包。
- 支持 SRT/ASS/SSA/VTT、文本 SUB、PGS SUP，以及 Store/Deflate ZIP。RAR/7z、加密/分卷/ZIP64、不支持的压缩算法、IDX/SUB 二进制配对显示明确未支持原因。
- ZIP 中央目录在构造条目对象前限制为 200 项/256 KiB；所有条目先检查路径、Windows 保留名/ADS、链接和重复名。单字幕 8 MiB、每包有效候选展开 32 MiB、压缩比 200；每批实际准备预算为 200 文件/128 MiB，验证失败的副本同样占用预算。
- 原生 Python 持有路径、扫描行、下载身份；远程网页仍没有 QWebChannel。本阶段没有新通信动作接受路径或系统命令。
- 同一下载 ID 只能成功登记一次；网页刷新不会再执行导入。已有扫描改变时拒绝旧下载关联，当前扫描中的其他审阅修改不丢弃下载队列，也不覆盖用户决定。
- 冻结预览前复核导入副本身份；冻结后继续使用原执行前复查和一次性确认凭证。文件冲突仍由原规则编号或在冻结后被阻止，绝不覆盖。
- 原下载、收据及未使用候选保留在暂存目录；只移动已确认的准备副本。错误副本可能保留但不登记/执行，不自动递归清理缓存。
- 关闭应用/重新扫描会清空本次库存和人工审阅，缓存仍留存。当前不从收据恢复跨会话库存；独立原型及系统浏览器下载仍不直接导入工作台。
